# Design System: Premium product one-shots

## Overview

**Creative North Star: "Recognizable working scenes"**

Operate mode governs the fifteen product surfaces; Experience mode governs the screenshot gallery. The built world combines populated collaborative boards, compact desktop management consoles and dark monitoring surfaces. Product identity comes from navigation, working geometry, information hierarchy and restrained accents, rather than a shared decorative theme.

These are original HTML/CSS/SVG studies informed by public product conventions and documented workflows. They do not claim exact fidelity to a particular release. Accounts, activity, quotas and costs are illustrative; selected actions are local demonstrations with no connected backend. Acceptance evidence covers desktop screenshots, not a validated mobile experience.

## Colors

Each HTML owns its inline CSS custom properties and product overrides; there is no external shared token package. Light consoles generally use white panels against cool pale backgrounds, dark text and quiet gray separators. Dark consoles use near-black backgrounds, slate panels and pale text. Green and amber/red communicate health, remaining capacity and warnings alongside labels.

Product accents are Miro blue (`#4262ff`), FigJam violet (`#8c4ce6`), Lucidchart orange (`#ce8b36`), Whimsical muted purple (`#9060ad`), Mural berry (`#b6466e`), OpenCodex sky blue (`#75b9ef`), CPA blue (`#327bfa`), Magpie graphite (`#4c515e`), EasyCLIProxy teal (`#078a87`), Quota Tray cyan (`#38c7e3`), CC Switch blue (`#1684f8`) with orange add actions (`#ff7918`), 9Router peach (`#e6a06e`), Claude Code Router clay (`#ce997d`), Usage blue (`#558bcf`) and Tokscale green (`#65c68c`). The gallery uses muted indigo (`#5c5f8e`). Tinted selection backgrounds derive from the local accent; pastel board fills carry workshop groupings and notes.

## Typography

The sans stack declares Inter followed by native system UI fallbacks (`-apple-system`, BlinkMacSystemFont, Segoe UI, sans-serif). Files do not load an external font, so the available system font supplies the native application convention. The common body size is 13px; small labels use roughly 9–11px, panel titles 13–14px and dashboard headings 25px. Tabular numerals align metrics.

Quota Tray and Tokscale use SFMono-Regular/Consolas/monospace within their main surfaces. Other consoles reserve this stack for endpoints, code and technical values. Board SVG text follows the sans stack. The gallery expands its heading to 44px with compact line height; product surfaces retain operational density.

## Layout

Canvas editors fill the viewport with a top bar, flexible dotted workspace, populated SVG scene and supporting inspector/outline. Dots repeat on a 20px grid. Floating tools, minimaps and zoom controls overlay the scene; Lucidchart additionally docks a shape library and formatting ribbon.

Management consoles use top chrome, left navigation, metric strips and table/card/chart regions. The common sidebar is 204px, with product overrides: Magpie 164px, CC Switch 165px and EasyCLIProxy 218px. Magpie, Quota Tray and Tokscale have bounded desktop frames; other consoles fill the page. Spacing is compact and varied, with frequent 4/8px control gaps and 18–28px content spacing rather than one strict universal scale.

The gallery has a 1240px maximum container, generous introductory space and two screenshot columns. Its previews preserve the captured desktop aspect ratio. CSS collapses gallery columns and simplifies app navigation/inspectors at smaller widths; these adaptations are implemented but desktop remains the acceptance scope.

## Elevation & Depth

Console panels primarily separate through thin borders and tonal backgrounds. Floating board rails, bottom docks, zoom controls and minimaps use soft offset shadows to distinguish tools from canvas content. Magpie's outer frame has a broader ambient shadow; CC Switch's active agent tab has a small lift. Sticky notes use modest shadows; terminal surfaces remain comparatively flat.

## Shapes

Controls generally have gently rounded corners (5–8px), panels around 10px, and selected larger cards/frames 12px. Avatars are circular; provider marks are rounded squares. Canvas geometry is product-specific: square sticky notes, pastel workshop sections, orthogonal flowchart connectors, smooth mind-map branches and a prioritization matrix. Icons are inline SVG with consistent rounded strokes, commonly 1.7px.

## Components

Buttons use compact icon/text arrangements, accent-filled primary actions, quiet outlined secondary actions and tinted active tools. Hover changes background or brightness; keyboard focus has an accent outline. Selects, pills, status badges and progress bars keep configuration and capacity readable. Tables use separators and aligned numeric columns. Shared primitives are embedded independently in each file; their similarity does not imply identical product architecture.

## Do's and Don'ts

- **Do** preserve each product's distinct working scene, accent and navigation conventions.
- **Do** keep real content density, readable labels, aligned metrics and visible state cues.
- **Do** keep artifacts self-contained with inline styles, SVG and local demo data.
- **Do** judge final desktop composition from screenshots and record limitations honestly.
- **Don't** turn all fifteen surfaces into the same dashboard or canvas composition.
- **Don't** imply connected administration, live usage data or exact-release reproduction.
- **Don't** introduce externally loaded fonts, icon libraries or decorative assets that compromise portability.
